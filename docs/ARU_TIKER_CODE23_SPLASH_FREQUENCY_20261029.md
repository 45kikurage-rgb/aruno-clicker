# Aru-Tiker code23 — 6番以降スプラッシュ頻度切替

2026-10-29 ユーザー追加仕様
- アプリHOMEに「6番以降から開始 スプラッシュあり」「6番以降から開始 スプラッシュなし」を維持する。
- フロートは **スプラッシュ ON/OFF ボタン**、**6番目以降再生 ボタン**、**スプラッシュ頻度 1〜5件ごと選択**。横幅の狭いスマホでも44dpタッチ領域を保つため、頻度はAndroid Spinnerドロップダウンで1〜5から選ぶ。
- スプラッシュOFFでは6番以降を通常順次開く。スプラッシュONかつ頻度1なら6番を直接開いた後、7番以降の各登録済URLの前にTikTok Lite通常起動（Activityタスクのリセット）を入れ、約1.8秒後にURLを開く。
- 頻度2なら6,7番の後→8番前、頻度3なら6,7,8番の後→9番前。4,5も同じ方式。空欄は件数に数えず番号を維持する。
- 頻度/ON-OFFは**端末内のみ**保存し、サーバーのURLや待機秒数を変更しない。保存した設定は再起動後も読み込み、次のスタートから有効。再生中の変更は無効（フロートコントロールを無効化）。
- 現在のコード20からのURL起動失敗／前面未確認時スプラッシュ→次リンクの救済はON/OFFに関係なく維持。失敗スキップ後は頻度カウンタをリセットし、二重スプラッシュを回避。
- 手動停止/画面OFF/端末ロック/ユーザー補助切断では即時停止、保留中のURL起動は禁止。最後のURLの後は余計なスプラッシュを行わない。
- スプラッシュ＝TikTok Liteアプリの通常起動（NEW_TASK/CLEAR_TASK）であり、起動ロゴが画面に出ることはAndroid/TikTok側の仕様によって保証されない。動画が実際に再生されているかの判定ではない。
- package jp.aruno.clicker、existing certificate SHA-256 14e1d564276b56dfbc95888ce8108aafbdaf4da938f7d5b1ed0fb593f274ca3f は不変。v0.6.6/code23として同じ署名で上書き更新する。ユーザーのURLデータを削除しない。
- Androidのテストと本番へのAPK公開、実機確認/正式運用開始は別に判定する。

実施テスト: 1/2/3/5件の間隔、6番直接開始、空欄飛ばし、失敗復旧時カウンタリセット、途中停止/ロック、LOOP、Intent開始フラグ、ローカル選択保存、既存全機能の回帰。
