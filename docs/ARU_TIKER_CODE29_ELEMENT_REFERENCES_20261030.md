# Aru-Tiker code29: ×の要素と位置の参考データ

0.6.12 / versionCode29 / jp.aruno.clicker。既存の署名・設定・保存データを使って更新する。

## 利用手順

1. フロートを表示し、TikTokの確認したい画面へ移動する。
2. 「要素確認」。実行中のURLランナーを一時停止し、手動指定の時点で要素を取得する。
3. 赤枠は取得できた画面内の全要素、橙枠は候補、緑枠は選択。「候補次へ」「重なり切替」で選び直せる。
4. 要素がない×は「枠を指定」で囲む。位置指定は、抽出できた要素と区別して保存する。
5. 「緑枠は×ですか？」に「はい／いいえ」。どちらも参考データとして端末内に保存する。選択操作はTikTokへ転送しない。
6. フロートまたはHOMEの「参考データ送信」で未送信記録を中央へ送る。失敗分は端末に保持して再送する。自動再開はしない。

## データと判定の範囲

全画面のTikTok要素を対象とし、クリック可能な要素だけに限定しない。最大4,000要素までの親子関係、画面上の矩形、表示状態、クリック可否、クラス、ID、文字、説明と、それぞれが空であることを記録する。見えない祖先も構造確認用に保持するが、その文字・説明は保存しない。画面サイズ、密度、OS、機種、URL番号、回答、取得時刻も保存する。

文字・説明は各240文字まで。URL文字列は[URL]へ置換する。画像は取得・送信しない。取得不能・上限超過はcomplete=false、文字切り詰めはlabelsTruncatedとして残す。「全要素」はユーザー補助APIが公開する範囲であり、画像に描かれた図形そのものの抽出は保証しない。

候補の点数は確率ではない。明示的な×・閉じるの文字、閉じるID、小さくほぼ正方形で属性が空の要素、中央領域、クリック可否、近くの幅広い文字・ボタンとの上下関係を参考に順位を付ける。白いポップアップ全体の矩形は必須条件にしない。空属性・位置・大きさだけで自動クリックを許可しない。

取消・停止・画面OFF・サービス切断・画面回転では確認を終了し、取消では記録を保存しない。取得を別スレッドで実行し、世代番号で停止後の遅延表示を防ぐ。取得は手動のみ。この版で新たに動画6〜200の毎秒判定・未確定候補の自動クリックは導入しない。従来の明示的な×検出経路は維持する。

## 保存と中央参照

アプリ専用領域element-referencesにUUID単位でAtomicFile保存。最大100件・合計100MiB・1件4MiB。未送信を自動削除しない。1回の送信は最大20件。中央から同じrecordIdの保存済み応答を受けてから送信済みとして扱う。再送は同一ID・同一内容なら冪等、内容が違う同一IDは409で拒否する。

送信先: https://aruno-tiker-elements.45kikurage.workers.dev/v1/references

中央は非公開R2のreference-data/tiker-elements/records/に保存する。公開GET・一覧の経路は設けない。ARUNOMATICアプリには依存しない。

ChatGPTからの参照は、aruno-platform-opsのrequests/tiker-elements.jsonをoperation=read、execute=true、limit=1〜50として更新し、Tiker reference data deployment and scoped private readerを実行する。tiker-element-references artifactのmanifestとJSONを接続済みGitHubから取得する。デプロイ試験データはtests/へ分離する。実際の利用者の記録と混同しない。
